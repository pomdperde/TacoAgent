# 文件回退

文件工具 `file_edit`、`file_create`、`file_delete` 在写入前，将原始字节和版本信息持久化到当前工作区的 `.tacoagent/undo/`。工具成功返回 `change_id`。记录与进程生命周期无关，重新启动后仍可使用。

```powershell
# 列出操作，不显示文件内容
 taco rollback -w "C:\path\to\project"
# 撤销指定操作
 taco rollback "<change_id>" -w "C:\path\to\project"
# 隔离会话：-w 仍为原项目目录
 taco rollback "<change_id>" -w "C:\path\to\project" --user alice --session "<session_id>"
```

## 行为

- 编辑：恢复操作前的原始字节（保留换行）和文件权限位。
- 新建：删除该操作创建的文件，保留空父目录。
- 删除：恢复原始文件，包括二进制文件；不支持递归删除目录。
- 回退前：比较内容 SHA-256、长度、修改时间、文件标识和权限位。任何不一致都报告 `conflict`，不强制恢复。
- 文件被用户重新创建、删除、替换或修改时，不覆盖用户的新版本。
- 同一文件连续编辑应逆序回退；成功回退后，仅更新与修改前版本完全匹配的上一条操作记录，使其可继续回退。
- 重复回退已完成记录返回 `already_rolled_back`。
- CLI 回退复用会话归属检查与工作区执行锁，运行中不能从 CLI 回退。文件工具和回退还共享独立的跨进程操作锁。

## 并发和故障

写入先保存 `prepared` 日志，再执行磁盘变更，完成后保存 `applied`。记录未完成或不确定的操作不会自动回退。文件替换先移走原文件并再次检查版本，然后通过硬链接排他地发布新文件，避免覆盖期间新出现的同名文件。不支持硬链接的文件系统会报错，不降级为强制覆盖。

被移走的原文件保留在日志的 `captured_paths` 中，方便故障恢复；这样外部编辑器仍持有旧文件句柄时，其后续写入也不会因删除旧文件而丢失。冲突时若原路径已被其他写入者占用，被移走的内容会留在该位置供人工处理。日志和这些文件包含代码内容，需要与工作区一起保护、备份并管理保留时间。

这不是面向任意不协作进程的文件系统事务。IDE 不遵守应用锁，特别是持续持有旧句柄或并发更换父目录时，仍可能需要人工核对。回退按整文件拒绝冲突，不自动合并用户与 Agent 对同一文件的改动。

## 范围

- 只认领上述文件工具明确执行的操作；`command_run`、测试命令、外部进程或直接 `write_text()` 的副作用不自动认领。应通过 `file_delete` 删除需要可回退的文件，而非 shell 删除命令。
- 不自动在验证失败或节点异常时回退，避免丢失待修复现场。使用 CLI 显式选择操作。
- 旧 `restore_workspace_git()` 不再执行强制 checkout，返回 False；旧状态恢复会报告 `workspace_restored=False`。旧快照没有操作归属信息，不能作为覆盖用户文件的依据。
- `.git`、`.tacoagent`、符号链接、目录联接和硬链接文件不允许通过这些写工具修改或恢复。
- 当前按操作 ID 回退文件，不回滚 LangGraph 状态、TODO、数据库或外部 API 副作用。
